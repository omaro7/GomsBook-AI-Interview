## 001. 인공지능(AI)이란 무엇인가요?

### 답변

인간의 인식·추론·학습·의사결정 같은 지능적 작업을 컴퓨터가 수행하도록
하는 기술 분야입니다.

### 상세 설명

AI는 하나의 알고리즘을 뜻하지 않습니다. 규칙 기반 시스템, 머신러닝,
딥러닝, 생성형 AI처럼 다양한 접근을 포괄합니다. 면접에서는 AI ⊃ ML ⊃
DL의 포함 관계를 함께 설명하면 개념 경계가 명확해집니다.

### 면접 핵심

> 인간의 인식·추론·학습·의사결정 같은 지능적 작업을 컴퓨터가 수행하도록
> 하는 기술 분야입니다.

### 꼬리질문

**Q. 이 개념의 한계는 무엇인가요?**

어떤 기법도 모든 데이터와 문제에서 항상 최선은 아닙니다. 적용 가정이
깨지는 상황, 계산 비용, 데이터 요구량, 오류 유형을 확인하고 Baseline과
비교해 선택해야 합니다.

## 002. 머신러닝과 딥러닝의 차이는?

### 답변

머신러닝은 데이터에서 패턴을 학습하는 방법의 총칭이고, 딥러닝은 다층
신경망을 사용하는 머신러닝의 한 분야입니다.

### 상세 설명

전통적 머신러닝은 사람이 특징을 설계하는 경우가 많고, 딥러닝은 신경망이
데이터에서 계층적 표현을 함께 학습하는 데 강점이 있습니다. 데이터
규모·연산량·설명가능성·문제 유형에 따라 선택이 달라집니다.

### 면접 핵심

> 머신러닝은 데이터에서 패턴을 학습하는 방법의 총칭이고, 딥러닝은 다층
> 신경망을 사용하는 머신러닝의 한 분야입니다.

### 꼬리질문

**Q. 실제 시스템에서는 어떤 기준으로 선택하나요?**

정확도만 보지 않고 데이터 규모, 계산 비용, Latency, 해석 가능성, 변경
빈도, 실패 비용을 함께 고려합니다. 결정론적으로 해결 가능한 부분은
단순한 방법을 우선하고 필요한 부분에만 복잡성을 추가합니다.

## 003. 지도학습·비지도학습·강화학습의 차이는?

### 답변

지도학습은 Label로 학습하고, 비지도학습은 Label 없이 구조를 찾으며,
강화학습은 환경과 상호작용하며 보상을 최대화합니다.

### 상세 설명

세 방식의 핵심 차이는 학습 신호입니다. 지도학습은 정답 Label,
비지도학습은 데이터 자체의 구조, 강화학습은 환경에서 받은 Reward를
사용합니다.

### 면접 핵심

> 지도학습은 Label로 학습하고, 비지도학습은 Label 없이 구조를 찾으며,
> 강화학습은 환경과 상호작용하며 보상을 최대화합니다.

## 004. 신경망이란 무엇인가요?

### 답변

Weight·Bias·Activation을 가진 계산 단위를 여러 층으로 연결하고 Loss를
Backpropagation으로 최소화하는 모델입니다.

### 상세 설명

한 뉴런은 보통 z=w\^Tx+b를 계산한 뒤 Activation을 적용합니다. 여러
Layer를 쌓아 복잡한 함수를 표현하고, Forward 결과의 Loss를
Backpropagation으로 미분해 Weight를 갱신합니다.

### 면접 핵심

> Weight·Bias·Activation을 가진 계산 단위를 여러 층으로 연결하고 Loss를
> Backpropagation으로 최소화하는 모델입니다.

## 005. Transformer란 무엇인가요?

### 답변

Attention을 중심으로 시퀀스를 처리하여 토큰 관계를 직접 계산하고 병렬
학습에 유리한 신경망 구조입니다.

### 상세 설명

Transformer는 recurrence 대신 Attention을 사용해 멀리 떨어진 Token 사이
관계를 직접 계산합니다. 학습 시 병렬화가 쉽지만 표준 Self-Attention은
Sequence 길이에 대해 O(n²) 비용을 갖는다는 한계가 있습니다.

### 면접 핵심

> Attention을 중심으로 시퀀스를 처리하여 토큰 관계를 직접 계산하고 병렬
> 학습에 유리한 신경망 구조입니다.

## 006. Self-Attention이란?

### 답변

같은 시퀀스의 토큰들이 서로의 관련성을 계산해 문맥적 표현을 만드는
방법입니다.

### 상세 설명

입력 표현에서 Query, Key, Value를 만들고 Query-Key 유사도로 각 Value의
가중치를 정합니다. 같은 시퀀스 내부에서 계산하므로 Self-Attention이라고
부릅니다.

### 면접 핵심

> 같은 시퀀스의 토큰들이 서로의 관련성을 계산해 문맥적 표현을 만드는
> 방법입니다.

### 꼬리질문

**Q. 이 수식이 학습에서 왜 중요한가요?**

수식은 모델의 출력이 어떻게 점수·확률·Loss로 연결되고 그 Loss가 다시
Gradient를 통해 Parameter update로 이어지는지를 설명합니다. 각 항의
의미와 차원을 설명할 수 있어야 합니다.

## 007. LLM이란 무엇인가요?

### 답변

대규모 데이터와 파라미터로 언어 패턴을 학습한 모델이며 대표적인
Decoder-only LLM은 다음 Token을 예측하며 생성합니다.

### 상세 설명

LLM은 대규모 Corpus에서 Token의 조건부 확률을 학습합니다. Decoder-only
모델은 P(x_t\|x\_\<t)를 반복 계산하여 한 Token씩 생성합니다. 지식을
완벽히 저장한 데이터베이스가 아니므로 Hallucination과 최신성 문제가
존재합니다.

### 면접 핵심

> 대규모 데이터와 파라미터로 언어 패턴을 학습한 모델이며 대표적인
> Decoder-only LLM은 다음 Token을 예측하며 생성합니다.

### 꼬리질문

## 008. Embedding이란?

### 답변

텍스트·이미지 등을 의미적 특징을 반영하는 고차원 Vector로 표현하는
방법입니다.

### 상세 설명

Embedding의 핵심은 의미적으로 비슷한 입력이 Vector 공간에서도 가깝도록
표현하는 것입니다. RAG에서는 Document와 Query를 같은 Embedding 공간으로
보내 Cosine Similarity나 Dot Product로 후보를 찾습니다.

### 면접 핵심

> 텍스트·이미지 등을 의미적 특징을 반영하는 고차원 Vector로 표현하는
> 방법입니다.

### 꼬리질문

**Q. 성능이 낮다면 무엇부터 확인하나요?**

먼저 정답 근거가 Top-K에 들어오는지 확인합니다. 없다면 Retrieval
문제이므로 Query, Chunking, Embedding, Top-K, Threshold, Metadata를
점검하고, 근거가 있는데 답이 틀리면 Prompt와 Generation 단계로 범위를
좁힙니다.

## 009. RAG란 무엇인가요?

### 답변

외부 문서를 검색해 관련 Context를 LLM에 제공한 뒤 근거 기반 답변을
생성하는 Retrieval-Augmented Generation입니다.

### 상세 설명

RAG는 먼저 외부 Knowledge Base에서 관련 Context를 검색하고, 그 Context를
Prompt에 추가한 뒤 LLM이 답을 생성합니다. 모델 Parameter를 다시 학습하지
않고도 변경되는 지식을 반영할 수 있다는 점이 Fine-tuning과 큰
차이입니다.

### 면접 핵심

> 외부 문서를 검색해 관련 Context를 LLM에 제공한 뒤 근거 기반 답변을
> 생성하는 Retrieval-Augmented Generation입니다.

### 꼬리질문

**Q. 성능이 낮다면 무엇부터 확인하나요?**

먼저 정답 근거가 Top-K에 들어오는지 확인합니다. 없다면 Retrieval
문제이므로 Query, Chunking, Embedding, Top-K, Threshold, Metadata를

## 010. AI Agent란 무엇인가요?

### 답변

목표를 이해하고 LLM 판단을 바탕으로 Tool과 외부 시스템을 선택·실행하는
시스템입니다.

### 상세 설명

Agent는 단순 Chat Completion보다 한 단계 넓은 실행 시스템입니다. LLM이
판단을 담당하고 Runtime이 Tool 실행·상태·반복·오류·권한을 관리합니다.
따라서 Agent의 품질은 답변 품질뿐 아니라 행동의 정확성과 안전성까지
포함합니다.

### 면접 핵심

> 목표를 이해하고 LLM 판단을 바탕으로 Tool과 외부 시스템을 선택·실행하는
> 시스템입니다.

### 꼬리질문

**Q. LLM에게 맡기지 말아야 할 부분은 무엇인가요?**

권한 검사, 허용 경로, Schema 검증, 최대 반복 횟수, Timeout, 승인 필요
여부 같은 안전 정책은 Application/Runtime이 결정론적으로 강제해야
합니다.

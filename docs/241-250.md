> 주제: Agent Workflow · HITL · 평가

## 241. AI Agent의 Workflow는 어떻게 구성되나요?

### 답변

Goal→Reason/Plan→Action→Observation→Next Action→Final Answer의 반복 실행
구조로 볼 수 있습니다.

### 상세 설명

Agentic 시스템의 핵심은 '모델의 판단'과 '실제 권한을 가진 실행'을
분리하는 것입니다. Tool allowlist, Argument/Schema 검증, 최대 반복 횟수,
Timeout, 승인, Audit Log 같은 제어는 LLM의 자연어 판단에만 의존하지 않고
Runtime에서 강제하는 것이 중요합니다.

흐름:
`Goal → Plan/Reason → Action → Observation → Next Action → Final Answer`

### 면접 핵심

> Goal→Reason/Plan→Action→Observation→Next Action→Final Answer의 반복
> 실행 구조로 볼 수 있습니다.

### GomsBook 프로젝트 연결

GomsBook AI Agent에서는 LLM 판단과 Tool 실행을 분리하고, EPUB 변경
작업은 승인 상태를 거쳐 적용하도록 설계할 수 있습니다. 조회 Tool은
자동화하고 수정·삭제·생성처럼 부작용이 큰 Tool에는 HITL과 Validation을
적용하는 구조가 적합합니다.

### 꼬리질문

**Q. LLM에게 맡기지 말아야 할 부분은 무엇인가요?**

권한 검사, 허용 경로, Schema 검증, 최대 반복 횟수, Timeout, 승인 필요
여부 같은 안전 정책은 Application/Runtime이 결정론적으로 강제해야
합니다.

## 245. Short-term Memory와 Long-term Memory 차이는?

### 답변

Short-term은 현재 Task/Session 상태, Long-term은 세션을 넘어 지속적으로
재사용할 정보나 지식을 저장합니다.

### 상세 설명

Short-term은 현재 Task/Session 상태, Long-term은 세션을 넘어 지속적으로
재사용할 정보나 지식을 저장합니다. 면접에서는 이 정의에 더해 적용 목적,
장점과 한계, 인접 개념과의 차이를 한 단계 더 설명하는 것이 중요합니다.

### 면접 핵심

> Short-term은 현재 Task/Session 상태, Long-term은 세션을 넘어
> 지속적으로 재사용할 정보나 지식을 저장합니다.

### GomsBook 프로젝트 연결

### 꼬리질문

**Q. 실제 시스템에서는 어떤 기준으로 선택하나요?**

정확도만 보지 않고 데이터 규모, 계산 비용, Latency, 해석 가능성, 변경
빈도, 실패 비용을 함께 고려합니다. 결정론적으로 해결 가능한 부분은
단순한 방법을 우선하고 필요한 부분에만 복잡성을 추가합니다.

**Q. 모든 Tool 실행에 승인을 받아야 하나요?**

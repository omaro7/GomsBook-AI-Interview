# GomsBook AI Interview 201\~210 상세판

> 주제: Retrieval 심화

## 201. Retriever의 역할은?

### 답변

Query와 관련성이 높은 문서 또는 Chunk를 찾아 LLM에 제공할 후보 Context를
선택하는 것입니다.

### 상세 설명

RAG에서는 Retrieval과 Generation을 분리해서 진단해야 합니다. 관련 근거가
Top-K에 없으면 Retrieval Failure이고, 근거가 있는데도 답변이 틀리거나
근거를 벗어나면 Generation Failure입니다. 따라서 단일 최종
정답률만으로는 개선 원인을 알기 어렵습니다.

### 면접 핵심

> Query와 관련성이 높은 문서 또는 Chunk를 찾아 LLM에 제공할 후보
> Context를 선택하는 것입니다.

### GomsBook 프로젝트 연결

GomsBook의 EPUB/XHTML RAG에서는 Query Embedding → project-scoped
Retrieval → Top-K/Reranking → Context Expansion → LLM Answer 흐름으로
연결할 수 있으며, Retrieval metric과 Generation metric을 따로 측정해야
합니다.

### 꼬리질문

**Q. 성능이 낮다면 무엇부터 확인하나요?**

먼저 정답 근거가 Top-K에 들어오는지 확인합니다. 없다면 Retrieval
문제이므로 Query, Chunking, Embedding, Top-K, Threshold, Metadata를
점검하고, 근거가 있는데 답이 틀리면 Prompt와 Generation 단계로 범위를
좁힙니다.

## 207. Chunking 전략의 Trade-off는?

### 답변

풍부하지만 검색 신호가 희석될 수 있습니다.

### 상세 설명

RAG에서는 Retrieval과 Generation을 분리해서 진단해야 합니다. 관련 근거가
Top-K에 없으면 Retrieval Failure이고, 근거가 있는데도 답변이 틀리거나

정답률만으로는 개선 원인을 알기 어렵습니다.

### 면접 핵심

> 작은 Chunk는 검색 정밀도가 높지만 문맥이 잘릴 수 있고 큰 Chunk는
> 문맥은 풍부하지만 검색 신호가 희석될 수 있습니다.

### GomsBook 프로젝트 연결

EPUB의 XHTML을 Chunking할 때 단순 문자 길이만 보지 않고
제목·문단·Section 구조를 활용할 수 있습니다. Child Chunk 검색 후
Parent/인접 문맥을 확장하는 방식은 EPUB 구조를 활용한 Retrieval 연구와

## 208. Parent-Child Context Expansion이란?

### 답변

작은 Child Chunk로 정밀 검색한 뒤 Parent나 인접 Chunk까지 확장해 LLM에
충분한 문맥을 제공하는 방법입니다.

### 상세 설명

작은 Child Chunk로 정밀 검색한 뒤 Parent나 인접 Chunk까지 확장해 LLM에
충분한 문맥을 제공하는 방법입니다. 면접에서는 이 정의에 더해 적용 목적,

### 꼬리질문

**Q. 왜 Child Chunk만 LLM에 전달하지 않나요?**

Child는 검색 정밀도에는 유리하지만 문맥이 잘릴 수 있습니다. 작은 Child로
검색하고 Parent/Neighbor를 확장하면 Retrieval precision과 Generation
context를 절충할 수 있습니다.

## 251. AI Agent와 Workflow의 차이는 무엇인가요?

### 답변

Workflow는 실행 경로가 주로 코드로 사전 정의되고 Agent는 현재 상태와
Observation을 바탕으로 다음 행동을 동적으로 선택할 수 있습니다.

### 상세 설명

Agentic 시스템의 핵심은 '모델의 판단'과 '실제 권한을 가진 실행'을
분리하는 것입니다. Tool allowlist, Argument/Schema 검증, 최대 반복 횟수,
Timeout, 승인, Audit Log 같은 제어는 LLM의 자연어 판단에만 의존하지 않고
Runtime에서 강제하는 것이 중요합니다.

### 면접 핵심

> Workflow는 실행 경로가 주로 코드로 사전 정의되고 Agent는 현재 상태와
> Observation을 바탕으로 다음 행동을 동적으로 선택할 수 있습니다.

### GomsBook 프로젝트 연결

GomsBook AI Agent에서는 LLM 판단과 Tool 실행을 분리하고, EPUB 변경
작업은 승인 상태를 거쳐 적용하도록 설계할 수 있습니다. 조회 Tool은
자동화하고 수정·삭제·생성처럼 부작용이 큰 Tool에는 HITL과 Validation을
적용하는 구조가 적합합니다.

### 꼬리질문

**Q. 실제 시스템에서는 어떤 기준으로 선택하나요?**

정확도만 보지 않고 데이터 규모, 계산 비용, Latency, 해석 가능성, 변경
빈도, 실패 비용을 함께 고려합니다. 결정론적으로 해결 가능한 부분은
단순한 방법을 우선하고 필요한 부분에만 복잡성을 추가합니다.

## 259. RAG Prompt Injection이란?

### 답변

검색된 외부 문서 안의 악의적 지시가 LLM Context에 들어가 Agent 행동을
조작하는 Indirect Prompt Injection 위험입니다.

### 상세 설명

RAG에서는 Retrieval과 Generation을 분리해서 진단해야 합니다. 관련 근거가
Top-K에 없으면 Retrieval Failure이고, 근거가 있는데도 답변이 틀리거나
근거를 벗어나면 Generation Failure입니다. 따라서 단일 최종
정답률만으로는 개선 원인을 알기 어렵습니다.

### 면접 핵심

> 검색된 외부 문서 안의 악의적 지시가 LLM Context에 들어가 Agent 행동을
> 조작하는 Indirect Prompt Injection 위험입니다.

### GomsBook 프로젝트 연결

GomsBook AI Agent에서는 LLM 판단과 Tool 실행을 분리하고, EPUB 변경
작업은 승인 상태를 거쳐 적용하도록 설계할 수 있습니다. 조회 Tool은
자동화하고 수정·삭제·생성처럼 부작용이 큰 Tool에는 HITL과 Validation을
적용하는 구조가 적합합니다.

### 꼬리질문

**Q. 성능이 낮다면 무엇부터 확인하나요?**

먼저 정답 근거가 Top-K에 들어오는지 확인합니다. 없다면 Retrieval
문제이므로 Query, Chunking, Embedding, Top-K, Threshold, Metadata를
점검하고, 근거가 있는데 답이 틀리면 Prompt와 Generation 단계로 범위를
좁힙니다.

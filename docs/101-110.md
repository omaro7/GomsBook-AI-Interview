## 101. RAG 검색이 틀렸는데 LLM이 정답이면 좋은 RAG인가요?

### 답변

아닙니다. 최종 답이 맞아도 올바른 근거를 찾지 못했다면 Retrieval 관점에서는 실패입니다.

### 상세 설명

RAG에서는 검색 단계와 생성 단계를 분리해서 보는 것이 중요합니다. 검색 품질이 낮으면 LLM이 좋은 생성 능력을 가져도 근거 기반 답변의 안정성이 떨어질 수 있습니다.

### 면접 핵심

> 아닙니다. 최종 답이 맞아도 올바른 근거를 찾지 못했다면 Retrieval 관점에서는 실패입니다.

### GomsBook 프로젝트 연결

GomsBook에서는 EPUB/XHTML을 검색 대상으로 삼아 Project-scoped RAG를 구성하고, Retrieval과 Generation을 분리 평가하는 방식으로 이 개념을 실제 검증할 수 있습니다.

## 103. Agent가 꼭 필요한가요?

### 답변

아닙니다. 결정론적 절차는 Workflow가 적합하고 동적 Tool 선택이 필요한 부분에 Agent가 유용합니다.

### 상세 설명

Agent 시스템에서는 LLM의 판단과 실제 실행을 분리해야 합니다. LLM은 다음 행동이나 Tool을 선택할 수 있지만 실제 실행, 권한 검증, timeout, retry, 승인 같은 제어는 Runtime 계층에서 결정론적으로 관리하는 것이 안전합니다.

### 면접 핵심

> 아닙니다. 결정론적 절차는 Workflow가 적합하고 동적 Tool 선택이 필요한 부분에 Agent가 유용합니다.

### GomsBook 프로젝트 연결

GomsBook AI Agent에서는 Agent Runtime과 Tool 실행 계층을 분리하고, EPUB 변경처럼 부작용이 있는 작업은 승인(HITL)과 검증을 거쳐 실행하는 구조로 연결할 수 있습니다.

### 꼬리질문

# GomsBook AI Interview 071\~080 상세판

> 주제: RAG · Retrieval · Agentic RAG

## 071. RAG 성능은 어떻게 평가하나요?

### 답변

Retrieval과 Generation을 분리해 Recall@K/MRR와 Correctness/Faithfulness
등을 봅니다.

### 상세 설명

RAG에서는 Retrieval과 Generation을 분리해서 진단해야 합니다. 관련 근거가
Top-K에 없으면 Retrieval Failure이고, 근거가 있는데도 답변이 틀리거나
근거를 벗어나면 Generation Failure입니다. 따라서 단일 최종
정답률만으로는 개선 원인을 알기 어렵습니다.

### 면접 핵심

> Retrieval과 Generation을 분리해 Recall@K/MRR와
> Correctness/Faithfulness 등을 봅니다.

### GomsBook 프로젝트 연결

GomsBook RAG 평가에서는 Golden Dataset을 기준으로 실제 Retrieval과
Answer를 실행하고 Context Precision/Recall, Faithfulness, Answer
Relevancy, NO_ANSWER 등을 분리 평가할 수 있습니다. 연구 단계에서는
개발용 평가셋과 Held-out Test를 분리하는 것이 중요합니다.

### 꼬리질문

**Q. 성능이 낮다면 무엇부터 확인하나요?**

먼저 정답 근거가 Top-K에 들어오는지 확인합니다. 없다면 Retrieval
문제이므로 Query, Chunking, Embedding, Top-K, Threshold, Metadata를
점검하고, 근거가 있는데 답이 틀리면 Prompt와 Generation 단계로 범위를
좁힙니다.

## 072. Recall@K란?

### 답변

관련 문서 중 Top-K 안에서 찾아낸 비율입니다.

### 상세 설명

관련 문서 중 Top-K 안에서 찾아낸 비율입니다. 면접에서는 이 정의에 더해
적용 목적, 장점과 한계, 인접 개념과의 차이를 한 단계 더 설명하는 것이
중요합니다.

### 핵심 수식

$$
\mathrm{Recall@K}=\frac{\#\{\text{relevant items in Top-K}\}}{\#\{\text{all relevant items}\}}
$$

### 면접 핵심

> 관련 문서 중 Top-K 안에서 찾아낸 비율입니다.

### GomsBook 프로젝트 연결

GomsBook의 EPUB/XHTML RAG에서는 Query Embedding → project-scoped
Retrieval → Top-K/Reranking → Context Expansion → LLM Answer 흐름으로
연결할 수 있으며, Retrieval metric과 Generation metric을 따로 측정해야
합니다.

### 꼬리질문

**Q. 이 개념의 한계는 무엇인가요?**

어떤 기법도 모든 데이터와 문제에서 항상 최선은 아닙니다. 적용 가정이
깨지는 상황, 계산 비용, 데이터 요구량, 오류 유형을 확인하고 Baseline과
비교해 선택해야 합니다.

## 074. MRR이란?

### 답변

첫 관련 결과의 1/rank를 여러 Query에 대해 평균한 값입니다.

### 상세 설명

첫 관련 결과의 1/rank를 여러 Query에 대해 평균한 값입니다. 면접에서는 이
정의에 더해 적용 목적, 장점과 한계, 인접 개념과의 차이를 한 단계 더
설명하는 것이 중요합니다.

### 핵심 수식

$$
\mathrm{MRR}=\frac{1}{|Q|}\sum_{q\in Q}\frac{1}{\operatorname{rank}_q}
$$

### 면접 핵심

> 첫 관련 결과의 1/rank를 여러 Query에 대해 평균한 값입니다.
